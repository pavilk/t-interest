# Учитывать категории интересов в рекомендациях людей

План опирается на модуль матчинга из `feature/matching`. На момент подготовки документа этого модуля ещё нет в `main`.

## Формула

`score = round(Jaccard(виды) + 0.20 × Jaccard(категории) + бонус_локации, 3)`

Jaccard — доля общих элементов среди всех уникальных элементов двух наборов. Если оба набора пусты, вклад равен нулю. Бонус за один офис остаётся `0.15`, за один город при разных офисах — `0.05`. Максимальный `score` вырастет с `1.15` до `1.35`.

| Интересы двух людей | Балл без бонуса локации |
| --- | ---: |
| Футбол и волейбол, у обоих только категория «Спорт» | `0.20` |
| Футбол и футбол, у обоих только категория «Спорт» | `1.20` |
| У обоих выбраны только «Технологии», конкретных видов нет | `0.20` |
| Футбол и театр, общих категорий нет | `0.00` |

## Данные и рекомендации

- Брать категории из сохранённых ответов на активный вопрос `v2_directions`. Добавить внутренний внешний ключ от варианта ответа к категории и миграцией связать семь стандартных вариантов с корневыми интересами. Обновить сиды. Уже заполненные анкеты заработают сразу после миграции.
- Учитывать одобренные явно выбранные категории, включая «Технологии» и «Спорт → Другое». Верхнеуровневое «Другое» и свободный текст баллов не дают. Конкретные виды по-прежнему берутся из `user_interests`.
- Допускать кандидата с заполненной анкетой, если совпал вид, категория или офис. Применять существующие исключения до лимита. Для пула из 500 сначала брать людей с общим видом, затем остальных, внутри каждой группы — по ID. Итоговую выдачу сортировать по убыванию `score`, при равенстве — по ID.
- Использовать одну формулу для рекомендаций и первого `like`, который создаёт пару. Сохранённые баллы существующих пар не пересчитывать.

## Контракт API

- Добавить в `GET /api/v1/recommendations/people` поле `common_categories` с массивом объектов `{id, name}`. Сортировать по имени и ID, при отсутствии совпадений возвращать `[]`.
- Оставить в `common_interests` только общие конкретные виды. Балл и оба списка совпадений строить из одного пакетного чтения интересов и категорий кандидатов. Обновить описание контракта для генерации типов фронта из OpenAPI.

## Проверки

- Проверить формулу на примерах из таблицы, частичном совпадении категорий, пустых наборах и бонусах локации.
- В PostgreSQL проверить рекомендацию по одной категории между разными офисами, приоритет общего вида при пуле больше 500 и исчезновение совпадения после снятия категории в анкете.
- Проверить миграцию на уже сохранённых ответах, её откат и повторное применение. Сверить `score` рекомендации и новой пары при одинаковых данных, а также сохранение балла при повторном `like`.
- Прогнать обычные и PostgreSQL-тесты, Ruff и mypy. Обновить описание матчинга в `AGENTS.md` и `CONTRIBUTING.md`.
